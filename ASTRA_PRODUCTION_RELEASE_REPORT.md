## Final release blockers fixed

### Explicit spreadsheet binding

Prepared code depended on `getActiveSpreadsheet()`, although Google documents bound active methods as unavailable in web-app execution. Code.gs now uses `openById` with the owner-confirmed production Sheet ID and fails closed when missing or inaccessible. No active-workbook fallback remains. The local harness maps that exact ID to an in-memory fake. Four focused regressions cover absent active context, missing ID, access denial and the actual legacy schema. See [Google bound-script documentation](https://developers.google.com/apps-script/guides/bound#special_methods).

Only A1:Z1 was read from the live Sheet, with 15 nonempty headers: timestamp, child_name, child_age, quran_level, session_language, parent_name, country, email, whatsapp, preferred_days, preferred_time, timezone, notes, consent, source. Tests prove the original order and prior rows remain unchanged while seven missing fields append: city_region, status, assigned_teacher, follow_up_date, internal_notes, submission_id, notification_status. The legacy timezone column is preserved. No customer rows were inspected.

### Browser cache mixing old scripts with new HTML

After the first release, the actual browser showed new booking response_token/acknowledgment code alongside old **Accept analytics / Reject analytics** controls. Public script/style responses had `Cache-Control: public, max-age=14400, must-revalidate`, while HTML had max-age=0. Fresh cached unversioned scripts could remain for four hours and suppress new conversion logic.

The follow-up versions only styles.css, consent.js and analytics-events.js as `?v=20260907-1` on every public page. Exact diff comparison confirmed the 18 HTML edits changed only those three URLs. main.js and backend/script contents are unchanged. A new regression failed on all 18 old pages before the fix and passes now; eight existing static assertion files were aligned with valid query-bearing URLs.
